# Tasterr v2.1.1 release evidence

- Release date: 2026-09-09
- Git tag: `v2.1.1`
- Evidence status: approved for release. Deterministic checks, dependency audits,
  security review, fresh changed-integration Plex contracts, and the explicitly
  accepted unchanged-integration Seerr exception passed the pre-tag gate. The
  immutable GitHub Release is the authoritative record for the final manifest
  digest, publication time, alias verification, and tagged-image smoke result.

## Scope

- Plex server discovery preserves a bounded remote-direct and relay fallback when
  local connections outnumber the identity-probe budget, while retaining
  deterministic local-first winner selection.
- `TASTERR_PLEX_MAX_CONNECTION_PROBES` configures three through twelve
  unauthenticated identity probes per advertised server resource and defaults to
  six. It remains server-side and applies to Continue Watching and Plex history.
- Plex URL, TLS, redirect, identity, token, resource-count, logging, and
  five-minute Continue Watching result-cache protections are unchanged. No Plex
  connection, resource token, or machine identifier is cached.
- Existing development dependencies were patched to resolve release-audit
  findings. Runtime dependencies are unchanged.
- Release preparation otherwise changes only version metadata, current release
  documentation and tests, living release specifications, and this evidence. It
  adds no runtime behavior, database, API, migration, or workflow change.

## Security review

- The complete `v2.1.0..HEAD` product scope was reviewed against
  `docs/SECURITY.md` with no release-blocking finding. No endpoint contract, session
  backend, database, migration, frontend runtime, or workflow changed. Import
  boundaries still prove that only `clients/` performs outbound HTTP and only
  `api/` shapes browser responses.
- Plex discovery retains HTTPS-only explicit-port `*.plex.direct` URLs, normal
  certificate and hostname verification, disabled redirects, unauthenticated
  identity probes, exact machine-identifier matching, and header-only resource
  tokens sent after verification. Discovery remains bounded to four resources
  and three through twelve probes per resource, with no cross-request connection
  state.
- The new probe limit remains absent from `PublicConfig`, runtime browser
  contracts, and OpenAPI. Logs and serialized responses contain no Plex token,
  URL, machine identifier, rating key, account identifier, title, or raw Plex
  payload.
- GitHub verification on 2026-09-09 confirmed a public repository, private
  vulnerability reporting, secret scanning with push protection, Dependabot
  alerts and security updates, and that immutable GitHub Releases are enabled.
  Squash-only merging, automatic head-branch deletion, read-only default workflow
  permissions, and active protected-main and immutable `v*` tag rulesets were
  confirmed with no bypass actors. All workflow actions remain pinned to full
  SHAs; package, artifact attestations, and OIDC write permissions remain
  confined to the image publish job.
- Uvicorn access logs remain disabled. No generated Playwright report, trace,
  HAR, coverage output, or log artifact is tracked. Repository fixtures and
  release material passed placeholder and client-contract regressions.
- Release evidence contains generic outcomes only and no credential, URL,
  identity, title, account/server identifier, viewing data, or raw upstream
  material.

## Upgrade and rollback

- Before upgrading, record the running immutable digest and take and validate a
  sensitive SQLite backup. Select `ghcr.io/zacharyarthur/tasterr:2.1.1`, pull,
  and recreate without building. This release adds no migration.
- Verify health, login, Home including Continue Watching where available, Plex
  history synchronization, detail, and one non-destructive request-state read
  after upgrade.
- Rollback to the v2.1.0 immutable digest against the existing v2 volume. To
  return to v1.1, keep a v2 image selected, stop the writer, downgrade migration
  `0006` to `0005`, and then start the prior immutable v1.1 digest; alternatively
  restore the matching validated pre-upgrade backup.

## Known limitations

- Plex items without a canonical TMDB GUID are omitted rather than title/year
  guessed; legacy-agent libraries may need an agent upgrade and metadata refresh.
- An inaccessible Plex share has no Tasterr allow/deny switch; remove its library
  access in Plex. Usable sibling servers continue to contribute.
- Continue Watching resolves at most twenty catalog details and uses a ten-second
  wall-clock deadline. Server discovery probes no more than the configured limit
  per resource, with up to four resources probed concurrently.
- Tasterr remains a single-process household service; multiple workers are not
  supported.
- One non-failing Starlette/httpx2 TestClient deprecation warning remains
  scheduled for dependency maintenance.

## Post-merge and post-tag record

After the release-readiness PR merges, the exact SHA candidate must pass manifest,
attestation, public visibility, anonymous pull, and disposable clean-install
checks before tagging. After `v2.1.1`, stable aliases, final digest, attestation,
and fresh tagged-install results are recorded only in the immutable GitHub
Release. No post-release source commit is created solely to record those later
facts.
