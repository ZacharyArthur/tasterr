# Tasterr v2.2.0 release evidence

- Release date: 2026-10-04
- Git tag: `v2.2.0`
- Evidence status: branch-verifiable release checks are complete, with the owner
  accepting the documented limitations. Publication remains conditional on exact
  text approval, protected-main merge and candidate/tagged-image verification.
  The immutable GitHub Release will record the final digest, publication time,
  stable aliases, attestation and tagged-image smoke outcomes.

## Scope

- Standard and 4K requests retain Seerr defaults unless an authorized user chooses
  a validated server, quality profile and root folder. Server-derived permissions,
  member-cookie request attribution and variant handling remain enforced.
- Household discovery can hide available/partial regular or 4K library titles and
  excluded subscription-service matches in the household region. Admin controls
  and explicit environment overrides preserve underlying stored preferences.
- Search, My List, Continue Watching, direct detail and taste-learning sources remain
  available. Subscription exclusions preserve selected-service narrowing, including
  complete overlap, and omit conflicting dedicated rails.
- Verification shares a five-second request budget, concurrency eight and at most
  three discover pages. Unknown titles stay visible. The catalog cache grows to
  4,096 entries; its byte use and live household working set are unmeasured.
- Confirmed saves cancel pending discovery reads and discard stale household blends;
  already-cached feeds remain visible during refresh. Active-filter hero fallback
  uses a surviving discovery rail, with independently checked eligibility.
- Release preparation advances version metadata, current documentation/support,
  regressions, locked security fixes and evidence. It adds no dependency, migration,
  product endpoint, authentication contract or workflow change.

## Security review

- The complete v2.1.1..main product scope was reviewed against docs/SECURITY.md with
  no source release blocker found. Request destinations require authenticated,
  typed reads and fresh Seerr identity/variant capabilities. Mutations retain
  CSRF and user-rate guards, validate destination membership before side effects
  and create requests with the member cookie, not the global read key.
- Admin settings retain admin/CSRF/rate guards, strict IDs, effective-value locks
  and preserved stored preferences. Explicit response models and PublicConfig keep
  credentials and internal URLs server-side. Outbound calls remain in clients,
  and bounded verification/refill work drains cancellation.
- React renders text/native controls; no browser secret storage, raw HTML,
  credential schema or migration was introduced. Existing SQLAlchemy persistence,
  hashed sessions and encrypted Plex tokens remain. Uvicorn access logs are disabled.
- Non-root digest-pinned builds and full-SHA workflow actions remain unchanged.
  Elevated package, artifact attestations and OIDC permissions remain confined to
  image publication. Generated browser artifacts remain ignored and fixtures are
  invented placeholders.
- GitHub controls verified on 2026-10-04: public repository, private vulnerability
  reporting, secret scanning/push protection, dependency alerts/security updates,
  SHA-pinned Actions, read-only default workflow permissions, squash-only merging
  and automatic head-branch deletion. Active main and v* tag rulesets have no bypass
  actors; main requires check/e2e/container-smoke/CodeQL, and tags forbid update and
  deletion; immutable GitHub Releases are enabled.
- Staged content was reviewed for private URLs, identities, viewing data,
  credentials, generated artifacts and attribution; no issue was found. The owner
  reports updating deployment access logging and explicitly accepts residual
  query-string exposure in deployment error logs for this release. This is an
  owner-approved exception to the proxy-redaction check, not independently
  verified runtime redaction. No infrastructure configuration or coordinates
  are recorded. Evidence contains generic outcomes only.

## Upgrade, rollback and limitations

- Record the running digest and take and validate a sensitive SQLite backup. After
  publication, select ghcr.io/zacharyarthur/tasterr:2.2.0, pull and recreate without
  building. This release introduces no migration.
- Verify health, login, Home, intentional-access lists and details, exclusions,
  applicable Plex history/Continue Watching and non-destructive request-state reads.
- Roll back to the prior v2.1.1 immutable digest against the existing schema. To
  return to v1.1, retain a v2 image, stop the writer and downgrade migration 0006 to
  0005, or restore the validated matching pre-upgrade backup.
- Cold caches/outages can leave unverified titles visible and subscription metadata
  follows existing cache freshness/stale windows. Cache capacity is an entry bound,
  not measured memory or a warmth guarantee. Browser journeys predate exclusions;
  new behavior has local API, unit and interaction coverage.
- Main candidate verification, anonymous clean installation, stable alias/digest
  checks and fresh tagged installation remain required before immutable publication.
