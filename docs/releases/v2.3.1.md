# Tasterr v2.3.1 release evidence

- Release date: 2026-10-08
- Git tag: `v2.3.1`
- Evidence status: approved for release on completed branch-verifiable checks and
  the owner's explicit manual-validation disposition. Protected-main merge and
  candidate/tagged-image verification remain required. The immutable GitHub Release
  will record final image digests, artifact attestations, publication time, stable
  aliases, and tagged-image smoke outcomes.

## Scope

- PR #45 fixes local email/password sign-in losing Seerr admin permissions and
  display names. The complete profile is read with the newly issued Seerr cookie
  before updating local identity or creating a Tasterr session.
- Missing or invalid permissions, mismatched identities, failed profile reads,
  and redirects fail closed with a generic error. Local-login unavailability
  emits a fixed WARNING without credentials or exception details.
- Plex sign-in and silent reauthentication are unchanged. No dependency, API
  shape, configuration, database schema, or migration change is introduced.
- Release preparation synchronizes package/lock versions, current documentation,
  version assertions, and living release-version references. OpenSpec is `n/a`:
  this patch restores existing specified behavior and otherwise updates metadata.

## Security review

- The full `v2.3.0..HEAD` product diff was reviewed against `docs/SECURITY.md`.
  Identity and permission validation precede local writes; the profile read uses
  only the freshly issued member cookie, an explicit five-second timeout, no
  redirects, typed parsing, and generic errors. The shared client stores no cookies.
- Existing session hashing, encrypted Plex tokens, auth/CSRF/rate guards, trusted
  proxy handling, browser secret projection, and hardened response headers remain.
  Uvicorn access logs remain disabled. No production endpoint, frontend runtime,
  dependency, migration, Dockerfile, or workflow change is introduced.

  reporting, secret scanning with push protection, dependency alerts/security

  main/version-tag rulesets with no bypass actors. Main requires check, e2e,

## Upgrade and rollback

- Back up and validate SQLite before upgrading to the pinned 2.3.1 image against
  the existing volume. This release adds no migration.
- Sign out and back in with local credentials after upgrading to refresh a stale
  admin flag or display name. Existing sessions do not refresh identity by themselves.
- Image-only rollback uses the prior known-good v2.3.0 digest and the same schema.
  Rollback across migration `0006` to v1.1 still requires the documented v2-image
  downgrade to `0005` or a validated matching pre-upgrade backup.

## Known limitations

- Local sign-in adds one bounded profile read. If Seerr cannot provide a complete
  valid identity, sign-in fails rather than saving incorrect permissions.
- Complete automated live Seerr testing and production proxy behavior were not
  reverified; the owner accepted manual candidate validation for this patch.
- Repository-wide strict OpenSpec validation rejects placeholder Purpose sections
  in eleven unchanged specifications. The modified release-readiness specification
  validates; those legacy documentation issues were not expanded into this patch.
- Final registry manifests, artifact attestations, anonymous pulls, candidate and
  tagged-image clean installs, stable aliases, and unchanged candidate digest are
  verified after release-preparation merge and recorded in the GitHub Release.
