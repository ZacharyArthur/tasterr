## Scope

- PR #40 lets members choose TV seasons when Seerr permits partial requests and
  multiple eligible seasons exist. Regular seasons start selected; Specials start
  off and appear only when Seerr explicitly permits them. Empty selection is blocked.
- Keeping every regular season selected preserves the whole-series request.
  Disabled or unreadable partial-request settings preserve ordinary requests.
  Explicit season submissions recheck the current policy and permissions.
- Standard/4K selection and advanced destinations are retained while choosing
  seasons. Cancel/Escape submit nothing; nested focus returns to the detail dialog.
- Rejected/no-op requests are failures without a success badge or taste signal.
  Specials remain excluded from the ordinary detail season list.
- Repository-managed CodeQL scans cover Actions, Python and TypeScript with pinned
  actions and scoped analysis permissions.
- Release preparation adds no product behavior, dependency or database migration.

## Known limitations

- Partial season selection requires Seerr's partialRequestsEnabled policy; Specials
  additionally require enableSpecialEpisodes and eligible episode data.
- Existing availability guards still block requests for a variant already requested,
  partially available or available. The selector does not override those guards.
- Automated live coverage exercises public season policy; explicit-season payloads,
  retry preservation and rejection handling are covered by mocked regressions and
  the real-backend browser fixture, not a live TV season round-trip.
- Registry manifests, artifact attestations, anonymous pulls, candidate/tagged fresh
  installs, alias resolution and unchanged candidate digest require the merged
  release commit. Record them in the GitHub Release after verification.
